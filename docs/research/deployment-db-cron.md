# Managed databases and serverless-cron alternatives that could remove the need for a server

## Summary
Verdict on "does this justify a server?": No. JobPilot's workload (Gmail poll every few minutes, job-board polls a few times a day, <1 GB data, one user) fits inside current free tiers with $0 out of pocket, and three concrete $0 architectures exist. (1) Python-native: Modal Starter ($30/mo free compute; modal.Cron for the pollers, @modal.asgi_app() for FastAPI, ~$7-8/mo of credit even with one always-warm container) + Turso Free (libSQL = SQLite dialect, 5 GB, 500M row reads + 10M row writes/mo, Tokyo region, no card) -- this keeps the existing FastAPI/SQLite code almost unchanged; the only real change is swapping the sqlite3 file for a libSQL URL because Modal Volumes are last-write-wins and not meant for a shared SQLite file. (2) Edge-native: Cloudflare Pages (static UI, 500 builds/mo) + Python Worker (FastAPI supported, beta, cron triggers supported since Apr-2025) + D1 (500 MB, 5M reads/day, 100k writes/day) + Cron Triggers (5 per account free) -- all $0 and served from Tokyo/Osaka/Seoul/Singapore PoPs, but Workers Free caps CPU at 10 ms/invocation, which a Pyodide Python worker parsing dozens of emails can exceed; budget for Workers Paid ($5/mo, 30 s CPU, 15-min cron duration) if it does. (3) Privacy-first Gmail leg: Google Apps Script time-driven trigger (as often as every minute; consumer quotas 90 min/day trigger runtime, 20,000 Gmail reads/day, 20,000 UrlFetch/day) reads Gmail with the user's own Google auth -- the refresh token never leaves Google -- and pushes parsed metadata to a Sheet or via UrlFetchApp to Turso/Neon/Supabase's HTTP APIs; combine with (1) or (2) for the UI/chat. Traps found while verifying: Neon Free gives 100 CU-hours/project/month with a 5-min autosuspend you cannot disable, so a poller firing every <=5 min keeps the 0.25 CU compute awake 24/7 (180 CU-h) and exhausts the allowance mid-month -- poll every 15+ min or use Turso; GitHub Actions' 5-minute schedule floor at 1-minute billing granularity = ~8,640 min/mo vs 2,000 free for private repos, plus documented delays/drops at the top of each hour, so it only works at >=30-60 min intervals; Cloud Run Jobs are billed instance-based with a 1-minute minimum per run (a 5-min poll = ~518k vCPU-s/mo vs 240k free), Cloud Scheduler gives only 3 free jobs per billing account, and a card-backed billing account is mandatory; MongoDB M0 has no Tokyo/Singapore/Seoul/Mumbai/HK/Osaka free regions on AWS or GCP (Taiwan asia-east1 only) and pauses after 30 idle days; Supabase Free pauses after 1 week of inactivity (a running poller prevents it) and allows 2 active projects; Turso Free archives groups after 10 idle days (same mitigation); Xata no longer has a managed free tier ($0.012/hr + $0.28/GB, us-east-1/eu-central-1 only) and PlanetScale has none (Postgres PS-5 from $5/mo); Val Town is Deno/TypeScript only with public vals and 10 MB SQLite on Free; Pipedream Free has a hard daily credit cap, 3 active workflows and polling triggers pinned to the slowest interval. Sensitive-data note: every hosted-cron option (GitHub Secrets, Cloudflare Secrets, Modal Secrets, GCP Secret Manager, Pipedream connected accounts) means a third party holds the Gmail refresh token encrypted at rest; only Apps Script (token stays in your Google account) or a machine you own avoids that.

Best pick: Modal Starter ($30/mo free compute; modal.Cron pollers + @modal.asgi_app() FastAPI, ~$7-8/mo of credit) + Turso Free (libSQL/SQLite-compatible, 5 GB, 500M reads/10M writes per month, Tokyo or us-east-1, no card). $0 out of pocket, Python 3.12 native, and the FastAPI/SQLite code ports with a connection-string change; optionally move the Gmail leg to Google Apps Script so the refresh token never leaves your Google account.
Runner up: Cloudflare Pages (static UI) + Python Worker (FastAPI, beta) + D1 (500 MB SQLite) + Cron Triggers (5 free, every-minute capable) -- fully $0 with no card and served from Tokyo/Osaka/Seoul PoPs, but Python Workers are beta and the 10 ms CPU/invocation cap on Workers Free likely forces the $5/mo Paid plan for email parsing.

  fit: Not Python (JavaScript/V8), and cannot host FastAPI or stream LLM output, but it is the only zero-server Gmail poller where the OAuth grant never leaves your own Google account (no refresh token stored on GitHub/Cloudflare/Modal). Typical pattern: every 5 min, Gmail.Users.Messages.list(q='newer_than:1d category:primary') -> parse subject/sender/snippet -> UrlFetchApp.fetch(Turso/Neon/Supabase endpoint) -> FastAPI (on Modal/Cloudflare/your PC) reads the DB. 288 runs/day at ~10-15 s each = 48-72 min/day, under the 90-min cap; 20,000 Gmail reads/day is ample.
  gotchas: 90 min/day total trigger runtime on consumer accounts: keep each run under ~18 s average at 5-minute cadence, or poll every 10 min. / Trigger times are randomized within the interval window; not suitable for exact-time needs. / Since the script is owner-only, the OAuth consent screen shows Google's 'unverified app' warning to you alone; docs do not spell out an exemption, but no verification is needed for personal use. / UrlFetchApp to Turso/Neon means the DB auth token lives in Apps Script Properties -- still inside your Google account, but treat it as a secret; the Sheet fallback keeps everything in Google Drive.
