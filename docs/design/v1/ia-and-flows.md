# Mita JobPilot · 信息架构与核心流程（交付物 B · v0.1）

配套 `tokens.css` v0.1。术语固定：**待复核**（低置信，进队列）· **待确认**（信息缺失的占位，不是状态）· **待核实**（岗位在招与否未经官方页面核对）· **待排期**（面试已定、时间未定）。

## 1. 对象模型摘记（页面与流程都以此为准）

- **周期 Cycle**：名称 · 类型（实习 / 新卒 / 中途）· 区域包 · 起止。全站数据按周期归属；邮箱账号与密钥是全局的。
- **申请 Application**：公司（原文）· 岗位（原文）· track · `autoStatus`（邮件 / 日历推导）· `userStatus`（手动，可空）· 显示状态 = userStatus ?? autoStatus；userStatus 非空即「已手动覆盖」· `ghosted`（最近事件距今超过阈值，默认 30 天，且非终态）· 来源集合 · 备注。
- **事件 Event**（append-only）：类型（申请记录 / 邮件 / 面试邀请 / 门户通知 / 状态变更 / 门户结果 / 备注 …）· JST 时间 · 来源徽标 · 摘要 · 关联邮件主题（原文）· 置信度 · `needsReview`。
- **面试 Interview**：所属申请 · 轮次 · 线上 / 线下 · 工具或地点 · 会议链接（可空 → 待确认）· 时间（可空 → 待排期）· 结果（可空）。
- **岗位 Job**：公司与行业 · 岗位名 · 四分徽标（`confirmed_open` / `to_verify` / `special_lead` / `excluded`）· 方向 tag · 薪资及口径 · 匹配度（分析判断）· 核验日期（可空 → 「待核实」）· 目击记录 · 官方入口 URL · 我的申请（可空）· 收藏 · 比较中。
- **记忆事实 MemoryFact**：类别 · 正文 · 引文 · 置信度 · 来源 · 时间 · 范围（全局 / 周期）· 状态（候选 / 活跃 / 已否决）· `replaces`。
- **待复核项 ReviewItem**：邮件主题 · 发件人域名 · 系统猜测（分类 + 公司 + 阶段 + 置信度）· 候选申请 2–3 个。
- **提议 Proposal**（确认卡片的数据）：摘要 · 变化前 / 后 · 来源（聊天 / 队列 / 页面动作）· 状态（待处理 / 已确认 / 已取消）。任何改本地数据的动作都先生成 Proposal。

## 3. 页面清单（13 + 2）

每页：目的 · 布局 · 必备元素。所有页面：`Main p-4 md:p-6 md:pr-gutter`，纵向 `space-y-5`，网格 `gap-4`；页面标题 `serif text-3xl`；日期一律 mono、JST。

### 01 看板 `/`
目的：一眼看到今天与本周要做的事，以及系统替我发现了什么。
布局：12 列。顶部 eyebrow 日期 + `hand-body` 问候（尾随琥珀 ✦）；KPI 四格一行；下方左 8 / 右 4。
- KPI：进行中流程数 · 本周截止数 · 7 天内面试数 · 待复核数（第四格高亮变体 `bg-cream-200 ring-2 ring-cream-400`，点击 → 待复核）。数字 `.num`，副文说明口径（「按用户状态计」）。
- 左：「今日与本周」待办列表，按 今天 / 明天 / 本周稍后 分段；条目类型：截止 · 面试 · 需跟进 · 门户待查看；每条：类型图标 · 公司与岗位（原文）· JST 时间 + 相对时间 · 来源徽标 · 行尾动作（门户待查看：外链「前往官方入口」+「回填结果」）。
- 左：「后续面试」：已确认（按时间）与 待排期 两个子区。
- 左底：「最近变化」事件流（流程 1 的入口），低置信条目带「待复核」标记与「接受 / 修正」行内动作。
- 右：「Mita 的提醒」AI 提示卡（`hand-body` 标题，2–3 条，每条一个跳转 chip）· 状态分布（12 态四组手绘横向堆叠条 + 图例，不用饼图）· 信息源健康条（每账号一个圆点 + 地址 + 最近同步时间，点击 → 信息源）。
- 空周期：整块空状态「这个周期还没有申请记录」+ primary「评估一条岗位」。

### 02 申请 Pipeline `/pipeline`
目的：按状态总览所有流程，找到某公司进行到哪。
布局：标题行右侧分段控件「表格 · 看板」；筛选行（状态组 · 周期 · track · 邮箱账号 · 关键词）；下方视图。
- 表格：容器 `rounded-2xl`，按 12 态分组（组头行显示状态 chip + 计数，空组折叠）；列：公司（原文）· 岗位 · 状态 chip（旁随「已手动覆盖」图标）· 最近事件（摘要 + 来源徽标）· 下一步 / 截止（mono）· 来源 · 打开。ghosted 行整行 `ink-400` + 斜体小标「长期沉默 · N 天」。
- 看板：四组各一泳道区，每态一列（横向滚动）；成功 / 结束两组默认折叠为计数条，点击展开。卡片：公司 · 岗位 · 下一步日期 · 来源徽标。
- 空状态：无筛选结果 vs 空周期两种文案。

### 03 申请详情 `/pipeline/:id`
目的：一家公司的全部事实与下一步，并处理待复核事件。
布局：面包屑 → 头部 → 左 8 时间线 / 右 4 侧信息。
- 头部：公司 · 岗位 · track tag · 周期 · 状态区（显示状态 chip；小字「自动状态：X · 来源 · 时间」；覆盖时显示「已手动覆盖」图标 + tooltip；「改状态」按钮 → 行内确认卡片）· 来源徽标组 · 外链按钮「前往官方入口」。
- 事件时间线（append-only，新在上）：每条 类型图标 · JST 时间（mono）· 来源徽标 · 摘要 · 关联邮件主题（原文，可折叠）· 置信度小字；低置信带「待复核」标记与「接受 / 修正…」。
- 右：面试子区（已确认 / 待排期，各带「回填结果」）· 门户待查看条目（外链 + 回填结果）· 备注区（手写体小标题，自由文本，保存即事件）· 关联账号。

### 04 岗位工作台 `/jobs`
目的：发现、评估、比较岗位；只读，不投递。
布局：左 240 筛选栏（sticky）+ 主区；主区顶部「评估这条岗位」输入 + 排序；卡片两列；底部比较托盘（选中 ≥1 时出现）。
- 筛选：关键词 · 方向 · 行业 · 招聘对象 · 招聘状态四分 · 匹配度区间 · 应聘进度 · 仅收藏。
- 排序：综合 / 匹配度 / AI 相关度 / 薪资 / 成长性 / 截止 / 公司名。
- 卡片：公司与行业 · 岗位名 · 四分徽标 · 方向 tag · 薪资及口径（mono，日元无小数）· 匹配度（`.num` 数值 + 小字「分析判断」）· 我的应聘状态 chip · 核验日期（未核验 → 「待核实」）· 来源徽标 · 动作：收藏 / 加入比较 / 查看详情 / 前往官方入口（外链）/ 记录备注。
- 「评估这条岗位」：粘贴链接或全文的输入框 + 「评估」；结果以评估卡展开（流程 2）。

### 05 岗位详情侧板 `/jobs/:id`
目的：读完一条岗位所需的全部判断依据。
布局：右侧滑出 560 宽，背景 `ink-900/20`；内容分节，底部 sticky 动作条。
- 节：完整工作内容 · 薪资口径 · 匹配理由 · 需补足的部分 · 成长空间与风险（分数旁标「分析判断」）· 是否要求先实习 · 未确认事项（待确认占位）· 官方来源与核验日期 · 目击记录（最近三次轮询：时间 · 结果）· 备注。

### 07 面试日程 `/interviews`
目的：知道每场面试何时、何处、用什么工具，并回填结果。
布局：左 4 月份概览 + 待排期计数；右 8 Agenda。
- 月份概览：7×6 小格，有面试的日子画手绘圆圈（`.hand-circle` SVG），今天用实心点；月份切换；下方「待排期 N 场」。
- Agenda：「已确认」按日分段（今天 / 明天 / 日期），「待排期」独立分区。每场：JST 日期时间（mono；待排期显示待确认占位）· 公司 · 岗位 · 轮次 · 线上 / 线下 · 工具或地点 · 会议链接（无则待确认占位，绝不画假链接）· 「跳到申请」· 「回填结果」。
- 空状态：「未来 30 天没有面试」。

### 08 对话 `/chat`（全页，ChatGPT 式）
目的：用语言查进度、评估岗位、操作整个系统；一切改动先提议，每一步操作可见。
布局：三栏。左：会话列表，默认收起为 48px 图标条（只显「新对话」+ 展开箭头），点击展开为 260 宽列表（按 今天 / 本周 / 更早 分组，每行标题 + 时间 + 待处理提议计数）；中：消息流 + 输入条，`max-w-3xl` 居中；右：预览侧板（560 宽，默认关闭，点动作卡后滑出）。
- 头部：34px 琥珀渐变「M」头像 · `hand` 「Mita」· 状态行（模型名 + 6px 圆点）· Claude / GPT 分段切换 · 「待处理提议 N」小标 · 会话标题（可改名）。
- 消息流：用户气泡 / AI 气泡；流式光标；**动作卡**（每一步系统操作一张：「已查询 Pipeline · 3 条」「已打开 株式会社アクメ 详情」「已搜索岗位 · 12 条」，含来源徽标 + 时间，可点 → 右侧预览侧板）；内嵌结果卡（虚线，如「本周截止 3 项」）；确认卡片出现在 AI 气泡下方（摘要 · 变化前 / 后 · 确认 · 取消；确认后折叠为「已确认 · 时间」小条）。

- 输入条：文本框（多行自动增高）· 语言小标 ja / zh / en · 发送；无语音。
- 空会话：hand-body 问候 + 4 个建议 chips（「本周有什么截止」「评估这条岗位」「Acme 进行到哪了」「帮我复核待复核队列」）。

### 10 待复核队列 `/review`
目的：快速裁决低置信的自动识别。

### 11 研究请求 `/research`
目的：把外部 AI 的研究结果规范地带进岗位库。

## 4. 核心流程（分步：页面 · 组件 · 状态变化）

### 流程 1 · 新邮件 → 自动分类 → 最近变化 → 详情 → 复核
1. 后台 · Gmail 只读同步拉到新邮件 · 信息源健康条「最近同步」更新为当前 JST 时间。
2. 后台 · 分类器给出 分类 + 公司 + 阶段 + 置信度。≥ 阈值：事件写入对应申请，`autoStatus` 可能推进（如 已申请 → 面试中）；< 阈值：事件仍写入但 `needsReview = true`，同时生成待复核项 → 侧栏「待复核」计数 +1，看板 KPI 第四格 +1。
3. 看板 · 「最近变化」顶部出现新事件行：来源徽标 Gmail · JST 时间 · 公司 + 摘要；低置信附「待复核」标记与「接受 / 修正…」。
4. 申请详情 · 用户点开 → 时间线中该事件 `bg-cream-200` 高亮 2s 后淡出；显示邮件主题（原文）、置信度小字、「待复核」标记。
5a. 申请详情 · 「接受」→ 标记消失，置信度小字改为「已人工确认 · 时间」；待复核项移除，计数 −1；无确认卡片（接受即确认）。
5b. 申请详情 · 「修正…」→ 确认卡片：摘要「把这封邮件改归到 Kappa Motors · 阶段 面试邀请」；变化前（分类 / 公司 / 阶段，line-through）→ 变化后；确认 / 取消。确认 → 原申请时间线追加「已改归 → Kappa Motors」条目（append-only，不删除），目标申请新增事件；待复核项移除。
6. 若该申请已有 `userStatus`，`autoStatus` 推进不改变显示状态；「已手动覆盖」tooltip 显示最新自动状态。

### 流程 2 · 粘贴 JD → 评估 → 存为手动岗位 → 记录申请
1. 岗位工作台 · 「评估这条岗位」输入框粘贴链接或全文 → 「评估」。
2. 岗位工作台 · 输入框下方展开评估卡（PaperCard）：流式文字 + 光标；头部「来源 手动 · 时间」。
3. 评估卡 · 结果：解析出的公司与岗位（原文，可改）· 匹配度 `.num` + 「分析判断」· 匹配理由 · 需补足 · 成长空间与风险 · 未确认事项（待确认占位，如「薪资：待确认」）· 四分徽标预设「待核实」· 核验日期「待核实」。
4. 评估卡 · 「存为手动岗位」→ 卡片列表顶部插入新岗位卡（来源徽标 手动，四分徽标 待核实，200ms 位移入场）；「丢弃」则关闭。
5. 岗位卡 / 侧板 · 「记录申请」→ 确认卡片：摘要「新建申请记录：Nimbus AI · Machine Learning Engineer」；变化前「无记录」→ 变化后「考虑中（用户状态）· 周期 2027 新卒」。

### 流程 3 · 语音改状态 → 提议 → 确认 → 已手动覆盖

### 流程 4 · 门户待查看 → 外链 → 回填结果
1. 后台 · 邮件「マイページをご確認ください」分类为「门户通知」（Hoshino Consulting，高置信）→ 事件类型「门户待查看」。

3. 用户点外链 → 新标签打开门户（系统不接触）；条目附加微标「已打开 · 时间」，状态不变。
4. 看板 / 详情 · 「回填结果」→ 小面板：单选 通过下一轮 / 收到面试安排 / 收到 Offer / 落选 / 其他（备注）；可选日期（留空 → 待确认）。
5. 提交 → 确认卡片：摘要「记录门户结果：收到面试安排」；变化前 自动状态 已申请 → 变化后 用户状态 面试中；新增事件「门户结果（手动）」。

1. 顶栏 · 周期切换器（「2027 新卒」）→ 下拉：每周期一行（名称 · 类型 · 区域包 · 起止 · 申请数）· 「管理周期…」。

### 流程 6 · 研究请求 → 导入特别线索
1. 研究请求 · 选模板「搜索新岗位」（`ring-2 ring-cream-400`）→ 参数（方向 · 地区 · 数量）。

5. 「导入 N 条」→ 确认卡片：摘要「导入 N 条为特别线索」；变化前「库中 M 条」→ 变化后「M+N 条」；小字「来源 研究请求 · 核验日期 待核实」。

### 流程 7 · LinkedIn 导出 ZIP 导入

### 流程 8 · 添加邮箱账号 → 授权 → 首次回填
1. 信息源 · 「添加账号」→ 列表末尾插入等待态行：「在浏览器中完成 Google 授权…」+ 三点动画 + 「取消」；小字「只请求只读权限：gmail.readonly · calendar.readonly」。
2. 授权完成 → 行变为正式账号：地址 · 健康「正常」· 最近同步「—」· 消息数 0。
3. 行内首次回填进度条「回填最近 90 天 · 1,240 / 3,800」；期间健康 pill 显示「正常 · 回填中」。
